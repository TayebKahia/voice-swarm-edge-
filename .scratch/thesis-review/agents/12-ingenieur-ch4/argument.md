# Argument review: thesis/ingenieur/ch4_implementation.tex (Ingénieur Ch4)

Dimensions: D1, D2, D4, D6, D10 (Template A). Line numbers refer to the chapter as it is now
(432 lines). I read the code the chapter describes, and ran it where marked, with
`~/miniconda3/envs/pfe_swarm/bin/python` from the repo root. The scripts are in the session
scratchpad. I edited nothing except this report. D3 is not assigned to either agent. The script's
one number FAIL (l.123) is reported here because it came to this agent as a lead.

## 1. Verdict

The chapter is ready after fixes. It is not ready as it stands. The structure matches prd §3.1
item 4 exactly. The chapter keeps all four promises made to it (Ch1 structure, Ch1 and Ch3's
third mechanism, and Ch3's uncached prefix). It is disciplined about naming what is not built.
Its write-once handling is clean.

Five sentences contradict the code or the results:
- detection "at the keyword offset", against a measured decision delay of 540 ms at p95;
- the 14% near-miss share;
- "any failure ... no command is published", when a server error body publishes a hold;
- world-frame velocities, which PyFlyt returns in the body frame;
- "the physics backend is what shows that those results" transfer. Another seed breaks both
  the formation and the separation on PyFlyt.

Seven MAJOR findings follow, chiefly:
- the recovery sentence, against Ch3's V3 decision;
- two harness claims (thread-affinity record, frame-lag reporting) that the code does not
  support;
- a sentence describing a command path that is not built;
- an unacknowledged gap between the validator's 2.0 m/s speed ceiling and the 3 m/s the
  backends allow.

Every fix is a rewording. None needs a new measurement. Two offer an optional code change.
