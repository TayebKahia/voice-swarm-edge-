# Argument review: thesis/ingenieur/ch3_architecture.tex (Ingénieur Ch3)

Dimensions: D1, D2, D4, D6, D10. Line numbers are the chapter as of this review (500 lines; five
lines were added at l.43-48, the reflex/cortex analogy, while the review was running, so every
line after 43 is the pre-review script's line + 5). Code was read and, where marked, run with
`~/miniconda3/envs/pfe_swarm/bin/python`. Nothing was edited.

## 1. Verdict

The chapter is structurally complete, keeps every one of Ch1's promises (P15 and P8 only
partly), and respects write-once ownership. It has one factual contradiction with the code: the
layer-2 position clamp. It also has three logical gaps in the preemption and budget design that
an examiner can reach from the code alone: queued utterances escape the ordering rule, the
cancellation cannot bound recovery when the trigger lands during transcription, and the reflex
budget is never decomposed. None of these needs a measured figure to fix. Each fix is either a
sentence of acknowledgement or a correction to the wording.

## 2. Scorecard

- D1 Structure: ISSUES (1). Outline matches prd §3.1 exactly and the opening states the plan. There is no closing hand-off to Ch4.
- D2 Argument coherence: ISSUES (13). 3 MAJOR, 7 MINOR, 3 NIT.
- D4 Claims and hedging: FAIL (6). 1 BLOCKER, 4 MINOR, 1 NIT.
- D6 Cross-document ownership: PASS. Layer 1 hands off to the Master in one paragraph. The selected configuration is named, not derived. The other document is always "the \emph{Mémoire de Master}". No hardcoded Master chapter number, no voice-UAV literature.
- D10 Examiner view: ISSUES (3). 1 MINOR, 2 NIT, plus the reproducibility list in §7.

## 6. UNVERIFIED

Fed the raw grammatical string `{"intent":"set_param"}` in LANDED or LANDING, it returns and dispatches a Hover (run: `LANDED set_param{} -> intent='hover'`). That contradicts ch3 l.342-346 for that input. On the deployed route the Pi validates before publishing (`pipeline.py:200-201`), so the state machine sees `{"intent":"hover"}` and no-ops it, and Ch3's prose holds. Not a Ch3 finding. The Ch4 scaffold already flags it (ch4 l.100-101). I did not search whether any harness feeds raw decoder output to `handle_command` directly; `eval/exp2.py` goes through the pipeline.
